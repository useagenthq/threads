# OpenTelemetry export (`@threads/otel`, `threads.otel`)

Traces are derived from the log. Nothing is recorded for them: an exporter reads committed
events, computes spans with a pure function, and sends each span once, when it closes, to an
OTLP/HTTP collector as JSON. Both implementations produce the same bytes for the same log, and
the goldens in `cases/` pin them (generated by `spec/tools/fixtures/otel.py`, never hand-edited).

## Spans

`spans(branch, lookup)` walks a branch's resolved chain (for a fork, its parent's prefix too) in
seq order. It returns the spans whose **closing event is in the branch's own segment**, each with
its `close_seq`. `lookup(branch_id)` reads another branch's chain, for parents (below). A span's
bytes depend only on events with seq ≤ its `close_seq`.

| Span | Opens at | Closes at | Name | Kind |
|---|---|---|---|---|
| turn | a turn opener: `user_input`, `woken` or a `message_received` the reducer opens a turn with | `turn_completed` or `parked` | `invoke_agent {agent_name}` | INTERNAL (1) |
| resumed turn | any event after a `parked` that closed a turn, other than a turn opener or another `parked` | `turn_completed` or the next `parked` | `invoke_agent {agent_name}` | INTERNAL (1) |
| model call | `model_request` | its `model_response`, `model_response_recovered` or `model_attempt_abandoned` | `chat {model}` | CLIENT (3) |
| tool call | `tool_call` | its `tool_result` | `execute_tool {name}` | INTERNAL (1) |
| continuation | `resumed`, once per pending call that can run (below) | its `tool_result` | `execute_tool {name}` | INTERNAL (1) |

- **A continuation** opens at `resumed` for each call that has a `tool_call` and no `tool_result`,
  is not waiting on its own approval (a `permission_decision{ask}` or `approval_requested` with no
  `approval_granted`/`approval_denied` after it) and was not denied (`approval_denied`: the loop
  writes the denied result after `resumed`, and that call never runs). Its parent is the resumed
  turn, and it links to the call's previous span (the tool span or the previous continuation).
- **Closing a turn closes its children.** `parked` or `turn_completed` closes every model, tool
  and continuation span still open, at the same `close_seq`. A tool or continuation span closed by
  `parked` gets `threads.parked`. Any other span closed this way gets status ERROR (message `cut`)
  and `threads.cut`. On main a cancel writes a `not_executed` result for every pending call before
  `turn_completed{cancelled}`, so `threads.cut` is defensive; no known path writes it.
- A `parked` with no turn open (a second park before anything else) opens and closes nothing.
- An event with no span to attach to (below) is not exported. So is every event outside a turn.

**Span events.** Each event below is attached to exactly one span, open when it commits, that
closes at or after it. Its name is the event type, its time the event's, and it has the
attributes listed plus `threads.seq`.

| Event | Attached to | Attributes |
|---|---|---|
| `permission_decision` | the call's open span, else the turn | `threads.permission.decision`, `threads.permission.source` |
| `approval_requested` | the call's open span, else the turn | `threads.call_id` |
| `approval_granted`, `approval_denied` | the call's open span, else the turn (while parked: the resumed turn, which it opens) | `threads.call_id` |
| `effect_begin` | the call's open span, else the turn | `threads.call_id`, `threads.effect.attempt` |
| `effect_commit` | the call's open span, else the turn | `threads.call_id` |
| `effect_unknown` | the call's open span, else the turn | `threads.call_id`, `threads.effect.reason` |
| `effect_resolved` | the call's open span, else the turn | `threads.call_id`, `threads.effect.outcome`, `threads.effect.by` |
| `tool_result_late` | the turn | `threads.call_id` |
| `retry_scheduled` | the next `model_request` of the turn whose `purpose` is not `compaction`, else the turn span when the turn closes first | `threads.retry.of` (the failed attempt's span id), `threads.retry.delay_ms` |
| `compacted` | the turn | `threads.compaction.trigger` (when set) |
| `compaction_failed` | the turn | `threads.compaction.stage`, `threads.compaction.reason` |
| `budget_exceeded` | the turn | `threads.budget.scope`, `threads.budget.limit` |

"The call's open span" is its tool or continuation span. The turn is the open turn span. Events
appended while parked open the resumed turn, so they land on it.

## Ids

- `span_id` = the first 8 bytes of SHA-256(`"threads-span\0" + branch_id + "\0" + event_id`) of
  the opening event, where `branch_id` is the opening event's own `branch_id`. A continuation hashes
  `event_id + "\0" + call_id`.
- `trace_id` = the first 16 bytes of SHA-256(`"threads-trace\0" + root_thread_id + "\0" +
  root_event_id`) of the span's root.
- An all-zero id has its last byte set to 1.
- A `threads.export.possibly_lost` span: `trace_id` = the first 16 bytes of
  SHA-256(`"threads-loss\0" + observer + "\0" + thread_id`), `span_id` = the first 8 bytes of
  SHA-256(`"threads-loss\0" + observer + "\0" + thread_id + "\0" + deleted_at`), `deleted_at` in
  decimal.

Strings are UTF-8. `vectors/otel-ids.json` pins them.

## Roots and parents

Every turn span has a trace and, optionally, a parent span:

- `user_input` is its own root.
- `woken` takes the trace of the turn whose `tool_call` its first cause (`tool_result_late`)
  answers; else it is its own root.
- A turn-opening `message_received` takes the trace of `envelope.provenance.root_request`
  (`{thread_id, event_id}`), with no parent span.
- A resumed turn takes the trace and parent of the turn it resumes, and links to its span.
- **A child thread's first turn** (`thread_started.parent`), through `lookup(parent.branch_id)`:
  - `subagent`: the parent event is an `agent_spawned`. The turn's parent is the tool or
    continuation span of its `call_id` open at the `agent_spawned` in the parent chain, and its
    trace is that span's.
  - `handoff`: the parent is the parent's turn span open at the `handoff`.
  - `team_member`: no parent span; the rules above apply.
  - If the parent branch is missing or doesn't read, or no span is open there, the turn keeps its
    own root and gets `threads.parent_missing`. Spans already sent keep their ids; only spans sent
    afterwards carry the fallback trace, so one event can end up in two traces.
- Model, tool and continuation spans are children of their turn, in its trace.

## Attributes (semantic conventions core v1.41.1)

The resource carries `threads.otel.semconv = "1.41.1"`, and `scopeSpans[].schemaUrl` is
`https://opentelemetry.io/schemas/1.41.1`. v1.42.0 deprecated every `gen_ai.*` name in favour of
the separate GenAI conventions, which have no release yet; moving there is a follow-up and a
deliberate golden change (the cache-write name becomes `gen_ai.usage.cache_write.input_tokens`).

Every span: `threads.tenant`, `threads.thread_id`, `threads.branch_id` (the exported branch),
`threads.seq.start`, `threads.seq.end`. A boolean `threads.*` flag is present only when true.

| Span | Attributes |
|---|---|
| turn | `gen_ai.operation.name = invoke_agent`, `gen_ai.agent.name`, `gen_ai.conversation.id` (the thread id); `threads.run_id` (the latest `user_input` at or before the opener, when there is one), `threads.turn.reason` (from `turn_completed`), `threads.parked`, `threads.parent_missing`. Status ERROR, message the reason, for every reason but `end_turn`, `cancelled`, `handoff` and `input_denied`. |
| model call | `gen_ai.operation.name = chat`, `gen_ai.provider.name`, `gen_ai.request.model`, `gen_ai.response.finish_reasons = [stop_reason]`, the usage below; `threads.model.attempt`, `threads.model.purpose` (`turn` or `compaction`). An abandoned attempt: status ERROR with its `reason` as message and `error.type`. |
| tool call, continuation | `gen_ai.operation.name = execute_tool`, `gen_ai.tool.name`, `gen_ai.tool.call.id`, `gen_ai.tool.type = function`; `threads.tool.effect_class` (from the latest pinned tool set, when the tool is in it), `threads.resumed` (continuations). `is_error`: status ERROR with the result's `origin` as message. |

**Model and provider.** The model is `thread_started.model`, then each `settings_changed`'s. The
provider is mapped: `anthropic`, `openai`, `bedrock` → `aws.bedrock`, `vertex` → `gcp.vertex_ai`,
`azure` → `azure.ai.openai`; any other passes through unchanged.

**Usage.** threads' `input_tokens` excludes cache reads and writes; the convention's includes all
input. `gen_ai.usage.input_tokens` = `input_tokens + cache_read_tokens + cache_write_tokens`
(absent cache fields count 0). If any of the three is `null` it is omitted. Each non-null field is
also exported on its own: `gen_ai.usage.cache_read.input_tokens`,
`gen_ai.usage.cache_creation.input_tokens`, `gen_ai.usage.output_tokens`,
`gen_ai.usage.reasoning.output_tokens`. A `null` is never sent as 0.

**Content** is off by default. With `content: true`: tool and continuation spans get
`gen_ai.tool.call.arguments` (the input's canonical JSON) and, when closed by a result,
`gen_ai.tool.call.result` (its `preview`); model spans closed by a response get
`threads.model.output_text` (its text parts, joined with nothing). These are the logged, already
redacted bytes. Prompts are never exported.

**Timestamps** are the opening and closing events' `time` × 10⁶ ns. An end before its start (a
clock step between processes) becomes the start, with `threads.clock_skew`.

**Pinned `gen_ai.*` names.** The goldens use only these, all in the v1.41.1 registry
(`model/gen-ai/registry.yaml`); `gen_fixtures.py` fails on any other:

```names

gen_ai.operation.name
gen_ai.provider.name
gen_ai.request.model
gen_ai.response.finish_reasons
gen_ai.tool.call.arguments
gen_ai.tool.call.id
gen_ai.tool.call.result
gen_ai.tool.name
gen_ai.tool.type

```

## OTLP/HTTP JSON encoding

`POST <traces endpoint>` with `Content-Type: application/json` (plus `Content-Encoding: gzip`
when compression is `gzip`). The body is RFC 8785 canonical JSON:

```
{"resourceSpans":[{"resource":{"attributes":[…]},"scopeSpans":[{"schemaUrl":"https://opentelemetry.io/schemas/1.41.1","scope":{"name":"threads","version":<package version>},"spans":[…]}]}]}
```

- A span: `traceId`, `spanId`, `parentSpanId` (absent for a root), `name`, `kind`,
  `startTimeUnixNano`, `endTimeUnixNano`, `attributes`, `events` and `links` (each absent when
  empty), `status` (`{"code": 2, "message"}` for ERROR, absent otherwise).
- Ids are lowercase hex. Times are decimal strings. `kind` is 1 (INTERNAL) or 3 (CLIENT).
- An attribute is `{"key", "value"}`, sorted by key. A value is `{"stringValue"}`,
  `{"intValue": "<decimal>"}`, `{"boolValue"}` or `{"arrayValue": {"values": […]}}`.
- A span event is `{"timeUnixNano", "name", "attributes"}`, in seq order. A link is
  `{"traceId", "spanId"}`.
- Spans are sorted by (`threads.branch_id`, `close_seq`, `spanId`).
- A batch holds at most 512 spans, never splitting spans that share a `close_seq`.

## The cursor, sync and losses

- The cursor is an `observer_cursors` row per (observer, branch); the observer is `otel` or
  `otel:<name>`. Cursor `c` means every span of the branch with `close_seq ≤ c` was acknowledged.
  A branch without a row starts at its fork point (`fork_at_seq`), or 0 for a root branch.
- `sync()` lists every branch (all tenants) whose head is past its cursor and isn't backed off,
  reads each chain, keeps the spans with `cursor < close_seq ≤ head`, posts them in batches, and
  after each 2xx moves each branch in the batch to its head (all its spans sent) or to its last
  acknowledged `close_seq`. A branch with nothing newly closed moves to its head without a send.
- A branch that doesn't read is skipped, reported with its code and the head it failed at, and
  backed off in memory: 1 s, doubling to 1 h, reset when its head moves.
- A deletion inserts one `observer_losses` row per registered observer (`observers`): the thread's
  committed events past that observer's cursor, summed over its branches. `sync()` sends each
  unreported row as a zero-duration `threads.export.possibly_lost` span at `deleted_at` (with
  `threads.tenant`, `threads.thread_id`, `threads.unchecked_events`, `threads.deleted_at`), after
  the branch batches, then sets `reported_at`.

## Configuration

An option wins over the traces variable, which wins over the generic variable, then the default.

| Setting | Option | Variables | Default |
|---|---|---|---|
| endpoint | `endpoint` | `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT` (as is), `OTEL_EXPORTER_OTLP_ENDPOINT` (+ `/v1/traces`, one `/` between) | none: `invalid_config` naming both variables |
| headers | `headers` | `OTEL_EXPORTER_OTLP_TRACES_HEADERS`, `OTEL_EXPORTER_OTLP_HEADERS` | none |
| protocol | — | `OTEL_EXPORTER_OTLP_TRACES_PROTOCOL`, `OTEL_EXPORTER_OTLP_PROTOCOL` | `http/json`; anything else is `invalid_config` ("only http/json is supported") |
| timeout (ms) | — | `OTEL_EXPORTER_OTLP_TRACES_TIMEOUT`, `OTEL_EXPORTER_OTLP_TIMEOUT` | 10000; not a positive integer: `invalid_config` |
| compression | — | `OTEL_EXPORTER_OTLP_TRACES_COMPRESSION`, `OTEL_EXPORTER_OTLP_COMPRESSION` | `none`; `gzip`; anything else: `invalid_config` |
| service | `service` | `OTEL_SERVICE_NAME`, then `service.name` in `OTEL_RESOURCE_ATTRIBUTES` | `threads` |
| resource | — | `OTEL_RESOURCE_ATTRIBUTES` | none |
| client certificates | — | `OTEL_EXPORTER_OTLP_CERTIFICATE`, `…_CLIENT_CERTIFICATE`, `…_CLIENT_KEY` and their `TRACES_` forms | not supported: `invalid_config` when set |

- An empty variable counts as unset.
- A list (`k=v,k=v`) is split on `,`, then on the first `=`; keys and values are trimmed and
  percent-decoded. An entry without `=` or with an empty key is `invalid_config` naming the
  variable. Header values never appear in an error or a log line.
- The resource: the `OTEL_RESOURCE_ATTRIBUTES` entries, then `service.name` (the service
  above), `telemetry.sdk.name = threads`, `telemetry.sdk.language` (`nodejs` or `python`) and
  `threads.otel.semconv`, which win over the variable's entries of the same name.
- `vectors/otel-env.json` pins the resolution.
