# spec/

The single source of truth that **both** the TypeScript and the Python implementations obey.

- `schema/`: the log line and wire formats. The Zod schemas in `typescript/packages/core/src/log/` are the source: `bun run schema:export` writes the JSON Schema here, and the Pydantic models are generated from it. Never edit the JSON by hand. snake_case, RFC 8785 lines. SQLite stores these exact line bytes and JSONL exports carry the same bytes, so storage, export and fixtures are one contract. See `schema/README.md`.
- `conformance/cases/<name>/`: input logs, scripts and expected results. Both implementations must pass every case, and a log written by one must replay identically in the other. See `conformance/README.md`.
- `tools/`: `gen_fixtures.py` (thin entry point; `--check` fails CI on any drift) runs the `fixtures/` package: `jcs.py` (restricted canonical JSON with UTF-16 key order), one module per case family, and `__main__.py`. `gen_store_sql.py` embeds `schema/store.sql` in both stores (`--check` fails CI on drift). `check_api.py` validates `api.json` against `schema/api.schema.json`, resolves every `$ref` in the spec, and cross-checks names, failure codes and the host API operations. Stdlib Python; passes the `python/` project pyright and ruff config.
- `api.json`: the public API contract between languages. For every public function, handle, protocol and data type: the TS and Python names (`forkPoints` ↔ `fork_points`), parameters (positional, or TS options object ↔ Python keyword-only), optionality and defaults, sync or async result types, typed failure codes and the one thrown `ConfigError`. Wire shapes are `$ref`s into `schema/`, never copies. `conventions` states the mapping rules; `choices` lists every choice the ADRs left open and the option taken. Its shape is `schema/api.schema.json`. Both packages' exports are gated against it.
  - **Failure codes, two closed lists.** The wire `ErrorCode` (`schema/events.v1.schema.json`) is what the log records. `ApiErrorCode` (`schema/api.schema.json`) is what public calls return and the log never records (`not_found`, `forbidden`, setup codes, ...). Every failure code in `api.json` and the host API is in one of the two.
- `schema/host-api/`: the host HTTP API. `openapi.json` (OpenAPI 3.1) lists the routes; each names the `api.json` method it wraps (`x-api`) and its failure codes (`x-error-codes`). `host-api.v1.schema.json` holds the request, response and projection shapes that `api.json` also references.
- `conformance/coverage.json`: every brief scenario mapped to a case, test, job or live gate, with `planned` or `implemented` status. See `conformance/README.md`.

A feature starts here, before any code is written in either language.
