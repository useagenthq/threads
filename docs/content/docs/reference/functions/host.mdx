Starts nothing until ready(). Its HTTP API also serves web UIs: the AI SDK UI message stream (useChat) at /v1/ui/ai-sdk/&#123;agent&#125; and AG-UI at /v1/ui/ag-ui/&#123;agent&#125;, with frames derived from the log; a browser chat key is scoped to the signed-in principal.

Import from `@threads/host` (TypeScript) or `threads.host` (Python).

## Parameters

<Field name="store" type={"Store"} required>
  The store every bound agent's threads, runs and host records live in. See [Store](/docs/reference/types/Store).
</Field>

<Field name="agents" type={"Record<string, Agent<unknown, unknown>>"} required>
  Keyed by the name channels, schedules and the HTTP API use.
</Field>

<Field name="channels" type={"Record<string, ChannelAdapter>"} default={"{}"}>
  A channel thread's replies are derived from its log, whatever ran it: each end_turn reply and each open approval card is a host-issued channel_send, issued after every run of the thread and, for a crash in between, again after ready(). A send with a result or a parked effect is never issued twice.
</Field>

<Field name="ceiling" type={"Partial<Policy.permissions>"}>
  The host ceiling every run this host starts or resumes is also decided under (Agent.run ceiling). Omitted: no ceiling.
</Field>

<Field name="telemetry" type={"Exporter"}>
  An exporter, such as otel(), that the host syncs every second and once more on stop() (bounded by 5 s). A failing collector is retried with back-off (1 s doubling to 60 s) and logged once per streak; runs never wait on it. Omitted: no telemetry. See [Exporter](/docs/reference/types/Exporter).
</Field>

<Field name="schedules" type={"readonly Schedule[]"} default={"[]"}>
  The schedules the host fires once ready() has run. Default [] fires none.
</Field>

<Field name="authenticate" type={"(request: Request) => Promise<Principal | null>"}>
  Maps an HTTP API request to a principal, or null for 401. Omitted: every /v1 route answers 401; channel webhooks still work.
</Field>

<Field name="authenticate(request)" type={"Request"} required>
  The incoming HTTP request, to read its headers or cookies: a fetch Request in TypeScript, a Starlette Request in Python.
</Field>

<Field name="messagePolicy / message_policy" type={"readonly MessagePolicyRule[]"} default={"[]"}>
  Rules that let one host agent start, send to, ask, monitor or cancel another beyond what a team grants (wait is decided as monitor). They decide after a team's grant and before default deny, for every op of every sender, and only add. Each (from, to) pair appears once (a repeat is refused at setup with duplicate_name), so a logged decision names its rule by from and to. A from or to that names no host agent is refused at setup (invalid_config); so is an empty allow, a rule to a host member that allows start, monitor or cancel, and a rule between host members that allows anything but send or ask (invalid_config, naming the rule). An agent gets the team tools only for the ops some rule with it as from allows. A rule that allows start makes its from a lead; one whose rules target only host members makes it a caller, in no team. Default []: everything else is denied. Every decision is logged as message_policy_decided.
</Field>

<Field name="members" type={"Record<string, HostMemberOptions>"} default={"{}"}>
  Host agents that run as one long-lived member per tenant, keyed by agent name. A host member is shared by every conversation in the tenant, its history included, so user-private work belongs in a started member instead. Every thread of the tenant may address one by its name, as messagePolicy allows. One turn that parks it (an approval, ask_user, an effect in doubt) holds every other conversation's mail until it resumes, so keep effectful tools off shared members. A restart starts a new thread with empty history. A caller's turn failure ends only that turn, and each unanswered ask closes failed. When the turn ends the member instead (its own thread budget, a failed rebind), the same append bounces each ask that turn took with the code member_ended, and the asker closes it at once. A host member with handoffs is refused at setup (handoff_in_team, naming members.&lt;name>). So is one with team, whose context policy turns compaction off, or with a tool that can need approval (or ask_user) but no approvers (invalid_config, naming members.&lt;name>; for approvers: "a host member is shared by every conversation in the tenant, so its approvals need approvers; add approvers to agent '&lt;name>'"). Default &#123;&#125;: none.
</Field>
