function tool(options: {
  name: Name;
  description: string;
  input: z.ZodType<Input>;
  output?: z.ZodType<Output>;

## Parameters

<Field name="name" type={"Name"} required />

<Field name="description" type={"string"} required />

<Field name="input" type={"z.ZodType<Input>"} required>
  Tool arguments are parsed with it at the boundary; its JSON Schema is the pinned input_schema.
</Field>

<Field name="output" type={"z.ZodType<Output>"}>
  TypeScript only. Pinned output_schema. A result that fails it is an error result; the effect still happened.
</Field>

<Field name="runs" type={"\"host\" | \"sandbox\""} default={"host"}>
  Where execute runs. host (the default) runs it in the host process. sandbox is reserved and not supported in this release: a sandbox tool fails setup with ConfigError capability_missing (Python at tool(), TypeScript at agent check() or the first run) and never executes. Not pinned: host and an omitted runs give the same ToolSpec and config_hash. Only "host" is supported today; "sandbox" is a setup error.
</Field>

<Field name="execute" type={"(input: Input, ctx: RunContext<Deps>) => Promise<Output>"}>
  runs host: required. The value is the result; a thrown error becomes an error tool_result the model sees.
</Field>

<Field name="effect" type={"EffectClass"} default={"unguarded"}>
  Undeclared tools are unguarded: uncertainty always parks.
</Field>

<Field name="dedupWindowMs / dedup_window_ms" type={"PosInt"}>
  Required exactly when effect is idempotent.
</Field>

<Field name="reconcile" type={"{ lookup: (effectKey: string, ctx: RunContext<Deps>) => Promise<LookupResult<Output>>; finality: \"final\" | \"nonfinal\" }"}>
  Required exactly when effect is reconcilable. finality is the tool's declared LookupCapability: the runtime accepts a not_found answer as final only when it is final; under nonfinal a not_found is treated as not_found_nonfinal and the call parks.
</Field>

<Field name="endsTurn / ends_turn" type={"boolean"} default={"false"} />
