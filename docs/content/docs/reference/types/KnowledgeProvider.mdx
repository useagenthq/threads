A provider only stores and searches: the host ingests documents at run setup, and the framework checks scope, bounds and logs every call, and presents hits as untrusted reference. Build one with local_knowledge() or an adapter factory.

<Callout>A protocol: adapters implement it.</Callout>

## Methods

### setup

Resolve credentials and check configuration on the host. Called by check() or the first run, before anything is pinned; never at import or construction. Creates no connection or client: those belong to a run. Retried on the next check() or run after a failure.

<Tabs items={["TypeScript", "Python"]} groupId="lang" persist>
<Tab value="TypeScript">

```ts
setup(): Promise<void>
```

</Tab>
<Tab value="Python">

```python

```

</Tab>
</Tabs>

**Throws** `ConfigError` for a definition that can't run.

### ingest

Admit one document version into the scope and return it with the new store revision. The same key with the same content returns the earlier version; the same key with other content is invalid.

<Tabs items={["TypeScript", "Python"]} groupId="lang" persist>
<Tab value="TypeScript">

```ts
ingest(scope: Scope, source: KnowledgeSource, key: string): Promise<Result<DocVersion>>
```

</Tab>
<Tab value="Python">

```python
async def ingest(
    scope: Scope,
    source: KnowledgeSource,
    key: str,
) -> Ok[DocVersion] | Err[Failure]
```

</Tab>
</Tabs>

<Field name="scope" type={"Scope"} required>
  The scope to admit the document into, issued by the host. See [Scope](/docs/reference/types/Scope).
</Field>

<Field name="source" type={"KnowledgeSource"} required>
  The document, binding included. Store the binding as given. See [KnowledgeSource](/docs/reference/types/KnowledgeSource).
</Field>

<Field name="key" type={"string"} required>
  The ingest's idempotency key, unique to this scope and content. Dedup on it.
</Field>

**Returns an error value** with one of these codes: `unavailable`, `timeout`, `invalid`, `scope_violation`.

### remove

Remove a document from the scope from the next revision on; searches as of an earlier revision still see it. A retried key is a no-op. No built-in tool calls it today.

### search

Return the passages in the scope that best match a query, best first. Return only passages from this scope; the framework drops and audits any other.

<Tabs items={["TypeScript", "Python"]} groupId="lang" persist>
<Tab value="TypeScript">

```ts
search(scope: Scope, query: string, options?: {
  k?: PosInt;
  sources?: readonly string[];
  asOf?: number;
}): Promise<Result<readonly KnowledgeHit[]>>
```

</Tab>
<Tab value="Python">

```python
async def search(
    scope: Scope,
    query: str,
    *,
    k: PosInt = 5,
    sources: Sequence[str] | None = None,
    as_of: int | None = None,
) -> Ok[Sequence[KnowledgeHit]] | Err[Failure]
```

</Tab>
</Tabs>

<Field name="scope" type={"Scope"} required>
  The scope to search, issued by the host. See [Scope](/docs/reference/types/Scope).
</Field>

<Field name="query" type={"string"} required>
  The search text, as the model wrote it in search_knowledge.
</Field>

<Field name="k" type={"PosInt"} default={"5"}>
  The most hits to return, a positive integer. search_knowledge passes the model's k (1 to 20, 5 when it gives none), and the framework also caps the total hit text at 16 KB.
</Field>

<Field name="sources" type={"readonly string[]"}>
  Search only these documents, by doc_id (the source_id). Omitted or empty: search every document in the scope.
</Field>

<Field name="asOf / as_of" type={"number"}>
  Search as of this store revision, a non-negative integer: a pinned fork passes the revision its snapshot recorded, so it sees the corpus its original run saw. Omitted: search the current revision.
</Field>

**Returns an error value** with one of these codes: `unavailable`, `timeout`, `invalid`, `scope_violation`.

### revision

TypeScript only. The store's current monotonic revision, recorded as snapshot.knowledge_revision at capture.

```ts title="TypeScript"
revision(scope: Scope): Promise<Result<number>>
```

<Field name="scope" type={"Scope"} required>
  The scope asking, issued by the host. local_knowledge keeps one revision for the whole store and ignores it. See [Scope](/docs/reference/types/Scope).
</Field>

**Returns an error value** with one of these codes: `unavailable`, `timeout`.
