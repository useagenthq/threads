### saveCase / save_case

Saves one completed turn, the first included, as a case in the spec/conformance layout: case.json (with expect, input.text and rubric), log.threads-ts.jsonl and log.threads-py.jsonl (the branch through the event before the turn) with matching expected.&lt;impl>.json (the recorded turn's events), artifacts/, model.json, stubs.json (effects), sandbox.json (read-only results by tool, args_hash and occurrence), extensions.json (hook decisions and recall) and line0.json (the recorded prompt prefix, for drift). No sandbox snapshot is needed: runEvals reruns it from recorded results only, so a case from any sandbox provider is portable. The case is built from typed values, valid against case.schema.json by construction; both languages' tests validate every saved case against it.

### replay

Re-renders every recorded model request of this branch from the log and checks it byte for byte against what was sent: the system prompt against its settings epoch, then the stored request bytes, then the rendered request of the events before it. No model or tool calls, no sandbox, no appends; a fork includes its parent's prefix. The first failure comes back with the failing request's seq; a branch with no model request replays trivially. Import ran this check once; replay() re-runs it against the code running now, so run it over real threads in CI to prove an upgrade still reproduces them.

### cancel

Durable cancel_requested; unsettled effects park. Tree-wide: every descendant subagent without agent_finished gets cancel_requested&#123;scope: tree&#125; too, recursively, and the parent records each child's agent_finished&#123;cancelled&#125; before its own cancelled. A control appends through the run's own writer when this process runs the branch, or takes the branch lease for the one append (Appended). When another process holds the lease it writes a durable inbox control item instead, which the holder applies at its next step boundary or dispatch fence (CancelAccepted, with the item's key). Authority is checked before either is written.

### compact

The outcome, compacted or compaction_failed, is in the timeline, not an error of compact(). branch_busy: a turn is in progress, one parked on an approval or a question included; try again when it ends. invalid_request: instructions is an empty string. invalid_transition: a compaction is already requested, or there is nothing to compact yet. branch_not_runnable: an inspection-only branch.

### cost

What this thread spent, in nano-units of its pinned currency (USD for agent()), with a conservative upper bound; null when its pinned policy has no currency or no model list (a pinned currency with an unpriced model gives an incomplete cost instead). With tree: true it also counts every subagent at any depth, each from its own log, in the root's currency (else the first priced subagent's); null when no readable thread in the tree has a currency, which means unknown, never zero, even when a subagent's log is missing. complete and bounded become false when some spend can't be counted: a thread priced in another currency, or an unpriced thread that called a model. A subagent with no log counts nothing but makes the total incomplete and unbounded, since nothing proves it spent nothing. Errors: a subagent's read error; log_corrupt when a finished subagent's log is missing (except a cancel's record of a child it never created: cancelled, usage unknown), a subagent doesn't name the spawn that started it, or the tree names a thread twice; cost_overflow past 2^53-1 nanos. Messages name the path of child thread ids. With a team, tree: true also walks every member the lead started, model- or operator-started and nested teams too; a member still starting counts zero and leaves complete true (it has made no model request), and a member whose branch is missing after its starter received its task notification, or whose parent is not the lead's member_started or thread_started, is log_corrupt.
