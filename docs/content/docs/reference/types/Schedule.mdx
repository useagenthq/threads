---
title: "Schedule"
description: "A cron schedule on a host."
icon: "Braces"
---

A schedule keeps one thread, created at its first occurrence, and each occurrence continues it: fired (a run of the agent with input), or skipped as missed (it fell due while no host ran), overlap (the previous run was still going) or removed (its agent is no longer served, or now pins another config than the thread was started with). A thread's pinned config never changes, so when the schedule's agent or that agent's config changes, the next occurrence starts a new thread; changing only the cron, timezone or input keeps the thread. Every decided occurrence is logged on that thread with occurrence id &lt;id>@&lt;scheduled instant, RFC 3339 UTC with milliseconds>. An occurrence is reserved when due with the agent, input and timezone of that moment, so a reservation still fires after its schedule is removed; one whose thread is deleted before it is decided is dropped and never logged.

## Fields

<Field name="id" type={"Name"} required>
  The schedule's name: lowercase letters, digits and underscores, up to 64 characters. Each firing records it, and the run's principal is issuer "schedule" with this as subject.
</Field>

<Field name="agent" type={"string"} required>
  A key of host(&#123;agents&#125;).
</Field>

<Field name="cron" type={"string"} required>
  A five-field cron expression (minute, hour, day of month, month, day of week, where 0 or 7 is Sunday) of numbers, *, lists, ranges and steps, read in timezone. Anything else is a ConfigError invalid_config.
</Field>

<Field name="timezone" type={"string"} default={"UTC"}>
  IANA name.
</Field>

<Field name="input" type={"Input"} required>
  What a run starts with: plain text or ordered input parts.
</Field>
