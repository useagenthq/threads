## Requirements

- [Bun](https://bun.sh) to run TypeScript.
- [uv](https://docs.astral.sh/uv/) and Python 3.12 or newer to generate the shared code, even if
  you only plan to use TypeScript. Python also uses them to run the package.

## Clone and build

Both languages share generated code built from `spec/`. Run the generator through uv so it uses
Python 3.12 rather than an older system `python3`. The first run creates `python/.venv`. Repeat the
same command after each pull.

```bash
git clone https://github.com/useagenthq/threads && cd threads
uv run --project python ./scripts/generate.sh
```

## Install your language

<Tabs items={["TypeScript", "Python"]} groupId="lang" persist>
  <Tab value="TypeScript">
    The packages live in a Bun workspace under `typescript/packages`. The simplest way to use them today is to add your app as another workspace package.

    <Steps>
      <Step>
        ### Install the workspace

        ```bash
        cd typescript && bun install
        ```
      </Step>
      <Step>
        ### Add your app as a package

        Create `typescript/packages/my-agent/package.json` and list the threads packages you need:

        ```json title="package.json"
        {
          "name": "my-agent",
          "private": true,
          "type": "module",
          "dependencies": {
            "@threads/core": "workspace:*",
            "@threads/anthropic": "workspace:*",
            "zod": "^4.6.5"
          }
        }
        ```

        Run `bun install` again from `typescript/`.
      </Step>
      <Step>
        ### Run your code

        Put the [Quickstart](/docs/quickstart) code in `typescript/packages/my-agent/index.ts` and run it:

        ```bash
        cd packages/my-agent && bun index.ts
        ```
      </Step>
    </Steps>

    | Package | What it adds |
    |---|---|
    | `@threads/core` | `agent`, `tool`, `sqlite`, `openThread`, memory, knowledge, the scripted model |
    | `@threads/anthropic`, `@threads/openai`, `@threads/ai-sdk` | Models |
    | `@threads/docker`, `@threads/e2b`, `@threads/daytona` | Sandboxes |
    | `@threads/mcp` | MCP servers as tools |
    | `@threads/supermemory`, `@threads/zep` | Hosted memory |
    | `@threads/host`, `@threads/slack`, `@threads/whatsapp`, `@threads/github` | The host and its channels |
    | `@threads/cli` | The `threads` command |
  </Tab>
  <Tab value="Python">
    To follow the tutorials from this clone, put `support.py` in `python/` and run it in the
    environment the generator created:

    ```bash
    cd python
    uv run python support.py
    ```

    The offline tutorials need no provider extra. Before using a real Anthropic model, add its
    extra with `uv sync --extra anthropic`.

    To use `threads` from your own project instead, create that project's environment before
    installing the clone in editable mode:

    ```bash
    cd /path/to/your-app
    uv venv --python 3.12
    uv pip install -e "/absolute/path/to/threads/python[anthropic]"
    .venv/bin/python support.py
    ```

    On Windows, run `.venv\Scripts\python` instead. Add the extras you need, comma separated in
    the editable path:

    | Extra | What it adds |
    |---|---|
    | `anthropic`, `openai`, `litellm` | Models (`threads.anthropic`, `threads.openai`, `threads.litellm`) |
    | `docker`, `e2b`, `daytona`, `modal` | Sandboxes |
    | `mcp` | MCP servers as tools (`threads.mcp`) |
    | `supermemory`, `zep` | Hosted memory |
    | `host` | The host server and `threads dev` / `threads start` |
    | `slack`, `whatsapp`, `github` | Channels |

    The core package needs only `pydantic`. The `threads` command lives in the selected environment:
    run `uv run threads` from `python/`, or `.venv/bin/threads` from your own project.
  </Tab>
</Tabs>

## Check your setup

From the clone's root, run the offline eval example in your language. It needs no API key or
network connection:

<Tabs items={["TypeScript", "Python"]} groupId="lang" persist>
<Tab value="TypeScript">

```bash
cd typescript && bun examples/evals.ts
```

</Tab>
<Tab value="Python">

```bash
cd python && uv run python examples/evals.py
```

</Tab>
</Tabs>

Both print `1 passed, 0 failed`. These commands check that the generated code and your selected
language run together. If you're working on the framework itself, return to the clone's root and
run the full suites instead:

```bash
cd typescript && uv run --project ../python --extra host bun run check
```

For Python, use `cd python && uv sync --all-extras && uv run pytest`. The TypeScript suite includes
tests against the Python host, which is why its full check asks uv for the `host` extra.

## API keys

Providers read their keys from the environment unless you pass them in code, for example `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `E2B_API_KEY` or `DAYTONA_API_KEY`. Each provider page lists its variables. Keys are never written to the log and never enter a sandbox.
