You'll build a small weather agent with one tool. First it runs on a **scripted model**, so it works offline with no keys. Then you swap in a real model.

<Steps>
  <Step>
    ### Set up threads

    threads isn't published yet, so run it from a clone. Follow [Installation](/docs/installation) for your language, then come back.
  </Step>
  <Step>
    ### Write a tool and an agent

    A tool is a name, a description, an input schema and a function. `effect: "read_only"` tells threads the tool changes nothing, so it runs without asking for approval.

    <Tabs items={["TypeScript", "Python"]} groupId="lang" persist>
    <Tab value="TypeScript">

    ```ts
    import { agent, scriptedModel, sqlite, tool } from "@threads/core";
    import { z } from "zod";

    const getWeather = tool({
      name: "get_weather",
      description: "Get the weather for a city.",
      input: z.object({ city: z.string() }),
      effect: "read_only",
      execute: async ({ city }) => `It is sunny in ${city}.`,
    });
    ```

    </Tab>
    <Tab value="Python">

    ```python
    import asyncio

    from pydantic import BaseModel

    from threads import RunContext, agent, scripted_model, sqlite, tool


    class WeatherInput(BaseModel):
        city: str


    async def get_weather(args: WeatherInput, ctx: RunContext[None]) -> str:
        return f"It is sunny in {args.city}."


    weather_tool = tool(
        name="get_weather",
        description="Get the weather for a city.",
        input=WeatherInput,
        effect="read_only",
        execute=get_weather,
    )
    ```

    </Tab>
    </Tabs>
  </Step>
  <Step>
    ### Script the model

    A scripted model plays back fixed responses in order. This one calls the tool, then answers.

    <Tabs items={["TypeScript", "Python"]} groupId="lang" persist>
    <Tab value="TypeScript">

    ```ts
    const model = scriptedModel({
      responses: [
        {
          content: [{ type: "tool_use", call_id: "c1", name: "get_weather", input: { city: "Paris" } }],
          stop_reason: "tool_use",
          usage: { input_tokens: 20, output_tokens: 5 },
        },
        {
          content: [{ type: "text", text: "It is sunny in Paris." }],
          stop_reason: "end_turn",
          usage: { input_tokens: 40, output_tokens: 8 },
        },
      ],
    });
    ```

    </Tab>
    <Tab value="Python">

    ```python
    model = scripted_model({
        "responses": [
            {
                "content": [{"type": "tool_use", "call_id": "c1", "name": "get_weather", "input": {"city": "Paris"}}],
                "stop_reason": "tool_use",
                "usage": {"input_tokens": 20, "output_tokens": 5},
            },
            {
                "content": [{"type": "text", "text": "It is sunny in Paris."}],
                "stop_reason": "end_turn",
                "usage": {"input_tokens": 40, "output_tokens": 8},
            },
        ]
    })
    ```

    </Tab>
    </Tabs>
  </Step>
  <Step>
    ### Run it

    `sqlite(":memory:")` keeps the log in memory for this example.

    <Tabs items={["TypeScript", "Python"]} groupId="lang" persist>
    <Tab value="TypeScript">

    ```ts
    const weather = agent({
      name: "weather",
      instructions: "Answer questions about the weather.",
      model,
      tools: [getWeather],
    });

    const result = await weather.run("What is the weather in Paris?", { store: sqlite(":memory:") });
    if (result.status === "completed") console.log(result.output);
    else console.log(result.status);
    ```

    </Tab>
    <Tab value="Python">

    ```python
    weather = agent(
        name="weather",
        instructions="Answer questions about the weather.",
        model=model,
        tools=[weather_tool],
    )


    async def main() -> None:
        result = await weather.run("What is the weather in Paris?", store=sqlite(":memory:"))
        print(result.output if result.status == "completed" else result.status)


    asyncio.run(main())
    ```

    </Tab>
    </Tabs>

    Run the file with `bun index.ts` or `uv run python main.py`. It prints:

    ```text
    It is sunny in Paris.
    ```

  </Step>
  <Step>
    ### Switch to a real model

    Replace the scripted model with a provider. The key comes from `ANTHROPIC_API_KEY`. The store `sqlite(".threads")` keeps every run on disk, so you can inspect, resume and fork it later.

    <Tabs items={["TypeScript", "Python"]} groupId="lang" persist>
    <Tab value="TypeScript">

    ```ts
    import { anthropic } from "@threads/anthropic";

    const weather = agent({
      name: "weather",
      instructions: "Answer questions about the weather.",
      model: anthropic("claude-sonnet-5"),
      tools: [getWeather],
    });

    const result = await weather.run("What is the weather in Paris?", { store: sqlite(".threads") });

    switch (result.status) {
      case "completed":
        console.log(result.output);
        break;
      case "parked":
        console.log("waiting on", result.reason);
        break;
      default:
        console.log(result.status);
    }
    ```

    </Tab>
    <Tab value="Python">

    ```python
    from threads.anthropic import anthropic

    weather = agent(
        name="weather",
        instructions="Answer questions about the weather.",
        model=anthropic("claude-sonnet-5"),
        tools=[weather_tool],
    )


    async def main() -> None:
        result = await weather.run("What is the weather in Paris?", store=sqlite(".threads"))
        match result.status:
            case "completed":
                print(result.output)
            case "parked":
                print("waiting on", result.reason)
            case _:
                print(result.status)
    ```

    </Tab>
    </Tabs>
  </Step>
</Steps>

## Results are values

A run never throws for an expected outcome. It returns one of these, keyed on `status`:

| `status` | Meaning |
|---|---|
| `completed` | The agent finished. `output` holds the final text. |
| `parked` | The run is waiting: for an approval, or for a decision about an action that may already have happened. See [Human-in-the-loop](/docs/control/human-in-the-loop). |
| `failed` | The run stopped with an `error` code, such as `max_turns` or `model_unavailable`. |
| `budget_exhausted` | A [budget](/docs/control/budgets) ran out. |
| `cancelled` | Someone cancelled the thread. |
| `handed_off` | The agent [handed the conversation](/docs/multi-agent/handoffs) to another agent. |

<Callout type="idea">
  A tool without `effect: "read_only"` asks for approval before it runs, so the run parks with `awaiting_approval`. See [Permissions & approvals](/docs/control/permissions) to allow it.
</Callout>

## Start with `codingAgent()`

A coding agent needs a model, a sandbox, the file and shell tools, permissions that don't ask
before every edit, memory and instructions. `codingAgent()` is `agent()` with those already
chosen, so it is one call:

<Tabs items={["TypeScript", "Python"]} groupId="lang" persist>
<Tab value="TypeScript">

```ts
import { codingAgent } from "@threads/coding";

const coder = codingAgent({ workspace: { localDir: "./app" } });
const result = await coder.run("Add a --json flag to the CLI and run its tests");
if (result.status === "completed") console.log(result.output);
```

</Tab>
<Tab value="Python">

```python
from threads.coding import coding_agent

coder = coding_agent(workspace={"local_dir": "./app"})
result = await coder.run("Add a --json flag to the CLI and run its tests")
```

</Tab>
</Tabs>

You get Claude Sonnet 5 (keyed from `ANTHROPIC_API_KEY`), a [Docker sandbox](/docs/sandboxes/overview)
with 2 CPUs, 4 GiB and no network, the sandbox tools under `{mode: "accept_edits", allow: ["bash(*)"]}`,
`localMemory()` and the `CODING_INSTRUCTIONS` the package exports. It needs a running Docker
daemon; `check()` answers `docker_unreachable` and names the alternatives when there isn't one.

**`./app` is copied into the sandbox, and your files on disk are never written to.** The answer
ends with a unified diff of everything the agent changed, which you apply yourself:

```bash
# paste the diff into changes.patch
git apply changes.patch
```

The copy skips `.git`, anything your `.gitignore` covers, and secret-looking paths (`.env*`, keys,
`.npmrc`), and refuses a file holding a [registered secret](/docs/production/deploying); the thread's
pin lists what was skipped. It takes at most 10,000 files and 256 MiB after those exclusions. Pass
`include: [".env.test"]` to re-admit one path, or `workspace: {git: {repo, ref}}` for a large tree.
A `localDir` is resolved once and pinned as bytes, so continuing the thread after `./app` changed
on disk fails closed with `invalid_config`: start a new thread.

**There is no internet in the sandbox**, so `npm install`, `pip install` and `git clone` fail.
"Run its tests" works when the dependencies are in the image or in files that aren't gitignored —
an ignored `node_modules` is not copied. To let a dependency install through:

<Tabs items={["TypeScript", "Python"]} groupId="lang" persist>
<Tab value="TypeScript">

```ts
import { docker } from "@threads/docker";

const coder = codingAgent({
  sandbox: docker({ allowInternet: true, cpus: 4, memoryMb: 8192 }),
  egress: "unenforced", // required: a bridge network filters nothing
  workspace: { localDir: "./app" },
});
```

</Tab>
<Tab value="Python">

```python
from threads.docker import docker

coder = coding_agent(
    sandbox=docker(allow_internet=True, cpus=4, memory_mb=8192),
    egress="unenforced",  # required: a bridge network filters nothing
    workspace={"local_dir": "./app"},
)
```

</Tab>
</Tabs>

Every default is one option away, and a key you pass replaces that default whole: see the
[`codingAgent` reference](/docs/reference/functions/codingAgent). `permissions: {mode: "plan"}`
starts read-only, `memory: undefined` (Python `None`) drops the memory tools, and
`instructions: CODING_INSTRUCTIONS + "\n\nThe repo is acme/app."` extends the defaults instead of
losing them. A thread from `codingAgent()` and a thread from the equivalent `agent()` call have
the same `config_hash`: the preset is those defaults and nothing else.

<Callout type="warn">
  `bash(*)` allows every command, because the sandbox is the boundary. Use
  [rootless Docker](https://docs.docker.com/engine/security/rootless/) or Podman: the Docker
  socket is root-equivalent on your machine. And if the directory you copy in contains the agent
  definition itself, the agent may edit its own config — nothing protects a file the framework
  doesn't know is config, so your review of the diff is the gate.
</Callout>
